# T+1 长期模型任务 Implementation Plan

## 需求规格

**目标：** T+1 模型不再只作为一次性执行入口使用，前端和命令行都必须提供长期运行任务；任务只有在用户手动停止、按下 `Ctrl+C` 或后端进程退出时才结束。

**范围：**

- 后端长期任务循环负责先确保最新交易日的 T+1 模型结果已经生成，再在开盘时执行实时模拟撮合。
- 同一交易日已经有 T+1 分析结果时，不重复消耗 LLM；如果本进程内已经处理过但结果为空，也不在每个循环重复请求模型。
- 状态写库失败不能中断长期循环，只记录日志。
- 前端 `T+1交易` 页面把一次性“运行T+1分析”入口升级为“启动T+1模型”，并在任务运行时自动刷新状态。
- 开盘时看板读取必须按持仓和候选股定向使用实时行情刷新持仓最新价、浮动盈亏、总资产和候选交易价；实时行情为空或单只持仓缺少 quote 时，只刷新 T+1 可卖数量并保留最近估值，不能在页面刷新时把实时任务写入的价格覆盖回日线收盘价。
- 命令行新增 `astocks-collector t1-loop`，长期运行直到用户手动中断。
- README 必须同步长期运行、手动停止和容器生命周期说明。

## 架构决策

- 复用 `T1RealtimeTaskManager` 作为唯一长期任务管理器，避免新增第二套任务状态表和停止语义。
- `T1TaskConfig` 扩展 `preselect_limit`、`use_llm`、`run_analysis`，让 API、前端和 CLI 共享同一份配置。
- `t1_simulation_task` 表通过兼容性 `ALTER TABLE` 补齐新增字段，旧库可平滑升级。
- `POST /api/t1-analysis/run` 保留为一次性调试/补跑接口；正式长期运行入口为 `/api/t1-trading/task/start` 和 `t1-loop`。
- `GET /api/t1-trading` 保持原有“读取看板时刷新估值”的模式，但估值源改为开盘定向实时行情优先、行情缺失时保留最近估值，保证页面刷新不会冲掉实时模拟资产状态。

## 实施清单

1. 修改 `src/astocks_collector/t1_task_manager.py`：长期循环加入 T+1 模型刷新、状态写库保护和新增配置字段。
2. 修改 `src/astocks_collector/t1_api_routes.py`：启动任务请求支持模型参数，并更新接口语义。
3. 修改 `src/astocks_collector/cli.py`：新增 `t1-loop` 长期运行命令，支持 `Ctrl+C` 手动停止。
4. 修改 `web/src/T1TradingSection.tsx`：一次性分析按钮改为长期模型任务启动，运行中自动轮询刷新。
5. 修改 `README.md`：补充长期任务命令、API、前端说明、容器生命周期和交付记录。
6. 修复看板估值：`T1TradingEngine.dashboard()` 开盘时按持仓和候选股定向读取新浪实时行情，并刷新持仓、账户和候选价格；实时行情缺失时保留最近估值；前端开盘或任务运行中按 5 秒/任务间隔轮询。
7. 增加实时行情兜底：`AkshareMarketData.fetch_realtime_quotes()` 支持传入股票代码列表，T+1 页面和任务优先使用新浪批量行情，避免容器内 AKShare 全市场接口断连导致 `quoteCount=0`。

## 验证计划

- 执行 Python 编译检查，确认后端语法正确。
- 执行前端 TypeScript 构建检查，确认新增字段和 React 逻辑类型正确。
- 不启动长期服务做真实任务验证，避免遗留进程；最终确认没有新启动的残留服务需要清理。
